# SpreadCore-аналог: Stake / Parimatch / Goated vs Polymarket

Сканер вилок между букмекерами (**Stake, Parimatch, Goated**) и **Polymarket**, работающий
в реальном времени через **WebSocket**. REST-запросы находят матчи, после чего цены сматченных рынков
приходят по WebSocket. Каждый тик сразу пересчитывает вилки этого матча, и алерт уходит
за миллисекунды. Алерты отправляются в Telegram и на дашборд, который тоже обновляется по WebSocket.

## Быстрый старт

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt

python -m spreadcore --mock --web          # демо на фейковых коэффициентах: http://127.0.0.1:8080
cp config.example.yaml config.yaml          # настроить
python -m spreadcore --once                 # один скан, вывод в консоль + ошибки источников
python -m spreadcore --web                  # постоянный скан + дашборд + Telegram
```

## Источники

| Источник | Поиск матчей | Живые цены | Статус |
|---|---|---|---|
| Polymarket | Gamma API | **WebSocket** стакана CLOB (`ws-subscriptions-clob`) | готов |
| Stake | GraphQL `/_api/graphql` | **WebSocket** GraphQL-подписки (`/_api/websockets`), при отказе — опрос | подписку стоит сверить с DevTools |
| Goated | Betby-фид или `jsonmap` | частый опрос (`interval: 3`) | нужно указать эндпоинт |
| Parimatch | `jsonmap` | частый опрос (`interval: 3`) | нужно указать эндпоинт |

### Как подключить Goated / Parimatch

```bash
pip install playwright        # на своей машине: playwright install chromium
python -m spreadcore.discover https://www.goated.com/sports
```

Откроется браузер. Залогиньтесь, если нужно, и покликайте по линии и **обязательно откройте пару лайв-матчей**:
именно в лайве сайты открывают WebSocket с коэффициентами. Утилита запишет:

- JSON-ответы с коэффициентами в `captures/NNN.json`;
- **все WebSocket-соединения** (в том числе из iframe) в `captures/ws/NNN.jsonl`: каждый отправленный
  кадр (это подписки, по ним видно, как подписаться) и полученный кадр (это обновления коэффициентов).
  Бинарные кадры распаковываются из gzip или deflate; если не получилось (msgpack или protobuf), сохраняются в base64;
- рейтинг HTTP-эндпоинтов и WebSocket-соединений по количеству коэффициентов в `captures/endpoints.json`.

Пришлите `endpoints.json`, верхний `captures/NNN.json` и верхний `captures/ws/NNN.jsonl`: по ним
адаптер пишется точно, включая живые обновления через WebSocket.
Если Playwright ругается на браузер, укажите свой Chrome: `--browser "/path/to/chrome"`.

- Если в выводе появилась строка `[Betby] api: ... brand_id: ...`, вставьте эти значения в `books.goated`
  с `type: betby` и `enabled: true`.
- Иначе откройте `captures/NNN.json` с наибольшим числом коэффициентов и пропишите пути к полям в секции `jsonmap`
  (пример есть в `config.example.yaml`). Синтаксис путей: `a.b[0].c`, `list[*]` (все элементы), `dict.*` (все значения).

## Как это работает

1. Каждый источник опрашивается по REST со своим `interval`. Это нужно, чтобы находить новые матчи.
   Polymarket и Stake после этого подписываются по WebSocket только на рынки, которые сматчились
   (Polymarket: до 400 токенов на соединение, с автоматическим переподключением и PING).
2. Имена команд нормализуются (FC/CF/акценты/алиасы) и сравниваются fuzzy-методом (rapidfuzz).
   Время начала должно совпадать в пределах `time_window_hours`. Пары вроде «X» и «X Women» или «X U21» не склеиваются.
   Если у одного источника хозяева и гости переставлены местами, это определяется автоматически.
3. Рынки: `ML2` (победитель, 2 исхода, включая овертайм) и `1X2`. Цена Polymarket `p` переводится
   в коэффициент `(1 - fee) / p`. Ask второго исхода считается как `1 - bestBid`.
4. Для каждого исхода берётся лучший коэффициент. Если `Σ 1/k < 1`, это вилка.
   Ставки распределяются так, чтобы выплата была равной.
5. Каждый WS-тик обновляет цену и ликвидность на лучшем уровне и пересчитывает вилки только
   в затронутых матчах (тики пачкуются по 50 мс). Новые вилки сразу уходят в Telegram и на дашборд.
   Если WS Polymarket лежит, ноги Polymarket перепроверяются по REST-стакану перед алертом.

## Важно

- Дашборд показывает индикатор `● live`, число тиков и список активных WS-потоков. Если поток
  источника пропал, сканер продолжает работать на REST-опросе.
- Адаптеры букмекеров работают через их внутренние API, а не официальные. Такие API меняются без
  предупреждения. Если источник отдаёт 0 событий, смотрите `errors` на дашборде или вывод `--once`.
- Автоматический парсинг может нарушать правила букмекеров, а за вилочную игру режут лимиты.
  Проверьте, что ставки и Polymarket легальны в вашей юрисдикции.
- Перед ставкой проверяйте коэффициенты вручную: в лайве они меняются за секунды.
